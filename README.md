场景实体后续的活动区域与资源管理方案见 [按 tile 管理生命周期](docs/tile-lifecycle.md)：每个 tile 持有活动 signal，玩家跨 tile 时更新区域差集，prefab 用 `createMemo` 派生活动状态。该方案尚未接入运行时。

## 调试命令（debugCommand）

开发模式（`pnpm dev`）在游戏左上角显示 FPS，每 0.5 秒按实际渲染帧数和 RAF 时间戳计算平均帧率；游戏暂停时仍显示渲染帧率，切换浏览器标签后重新采样。显示不拦截鼠标操作，显式停止场景时移除；生产构建不显示。调试命令的语法、参数和支持 ID 不变。

初始存档 `public/saves/initial-world.json` 保留以原点为中心、tile 中心距离不超过 20 格的陆地（本项目每格 12 世界单位，半径 240），外侧 5,792 格使用原版 `OCEAN_COASTAL`（地皮 ID `201`），已移除海洋格上的实体。加载器和 `c_save()`（无参数）支持保存、导出并重新加载这些海洋格，陆地上的实体身份和组件状态照常保存。近海使用原版 `levels/textures/ocean_noise.tex`、海域颜色及三层动态噪声；昼夜颜色纹理按原版九点核执行 3 轮横向／纵向模糊，然后进行 RGBA 昼夜混合、动态噪声与世界光照合成、2 倍编码及屏幕空间解码，详见 [海洋渲染管线](docs/dst-ocean-rendering.md)。地面积雪按 `ground_overlay.ksh` 乘上实际地皮 atlas 的 alpha，沿陆地伸入海洋格的岸边过渡区域渐隐，海面内部不积雪；挖地或耕地后同步更新遮罩。岸浪与浅海波纹播放结束自动移除，不参与存档；船只与海洋生物尚未接入。调试命令语法、参数和支持的 `c_spawn` / `c_give` ID 不变，海洋属于地图地皮。

入口在主场景资源、存档实体和交互绑定初始化完成并渲染完整场景后才关闭世界生成页；可等待 `src/main.ts` 导出的 `gameReady`，或检查主 canvas 的 `data-loaded="true"`。地皮 KTEX 解码由共享 Worker 完成，重复路径复用解码结果；纹理上传和世界／光照／后处理着色器分批预热，预热完成后才启动物理和游戏时间循环，`gameReady` 使用循环的首次渲染，不再额外绘制。加载失败时保留生成页并显示错误，开发模式也使用相同的加载等待。调试命令语法、参数及支持 ID 不变。

`PlaySound` 的统一音量倍率为 `0.7`，各音效的独立音量和距离衰减在此基础上叠乘；调试命令语法、参数和支持的 prefab/item ID 不变。

采摘产物统一交给 `Inventory.GiveItem()` 处理：先填充可用槽位和堆叠，背包满时把余量掉在玩家脚边，采摘仍然成功；采摘入口不再预加载或手动生成地面产物。地面贴图加载期间，掉落实体的 ID、数量、位置和组件状态仍可由 `c_save()` 保存。调试命令的语法、参数和支持的 prefab/item ID 不变。

草丛 `grass` 和洞穴花 `flower_cave` 的采摘／再生、灰烬 `ash` 的生成／拾取／移除，以及矮星 `stafflight` 的生成／消失／注销如何映射到 signal，见 [DST 事件与 signal 映射](docs/dst-event.md)。矮星已接入：私有 signal 保存寿命与移除标记，`createMemo` 派生 `active → disappearing → removed`，effect 只同步消失表现；计时和永久移除同步执行。远离卸载模型时释放表现绑定，保留逻辑状态与 memo；永久移除直接清理资源并释放 memo。草丛和洞穴花的再生／灯光 timer 已接入 signal：共享游戏时间调度器在设置、暂停、恢复、取消或到期时提交，等待期间不扣减 timer，memo 派生状态。灰烬消散的 timer signal 仍是后续方案。实体表现 effect 用 `get()` 订阅自身状态，用 `peek()` 读取环境，包含同步调用的辅助函数。调试命令语法和参数保持不变；补齐 `c_spawn("stafflight")`／`c_spawn("staffcoldlight")` 的注册入口。

`c_spawn("stafflight")` 在玩家位置生成一颗矮星，`c_spawn("staffcoldlight")` 生成极光，均无额外参数；也可用 `c_give("yellowstaff")`／`c_give("opalstaff")` 获取法杖施放。寿命分别保留 24／16 分钟，每 60 个有效游戏帧按累计实际 `dt` 结算，到期同步禁止保存，表现播放消失动画，实际到期点 1 秒后永久移除；消失动画完成只停止循环声。`c_save()` 无参数，先结算尾帧与远处经过的时间，只保存阶段为 `active` 的星体（包括远处未加载模型的星体）的 ID、位置与剩余寿命，读档恢复待机，不重播出现动画／音效。`getStaffLightState(model)` 提供寿命、移除标记与阶段的只读视图；管理器 `haunt(model)` 进入同一消失流程（幽灵输入尚未接入），`remove(model)` 显式移除，均不新增控制台命令。

库存实体直接提供数量、耐久、新鲜度和湿润状态的只读 signal，物品栏、装备、背包和容器 UI 订阅同一份组件状态；数值变化无需替换整份 UI item，数量接收动画读取实时 count。新鲜度和湿润显示使用原版 meter，缺少新鲜度状态时隐藏对应显示。可用 `c_give("torch", 2)` 检查燃料百分比，用 `c_save()` 保存并恢复库存组件状态；已提供的新鲜度与潮湿值也随库存／地面物品保存恢复。声明保鲜时长的物品已接入腐败模拟：`Perishable` 每 10 个游戏秒结算一次，内部通过 `watchSignal` 和 `createEffect` 监听潮湿状态，变化时按旧状态提前结算，随后潮湿倍率为 `1.3`；保存先结算不足 10 秒的部分，移除／释放组件时取消任务并清理监听。雨水吸收和干燥模拟尚未接入；命令语法、参数和支持的 prefab/item ID 不变。详见 [容器 DTO 与 UI signal](docs/inventory-architecture.md#容器-dto-与-ui-signal)。

地面物品的位置统一由 `entity.transform.position` 决定：移动与抛落写入实体，模型、脚点、拾取距离、换肤和保存读取实体坐标；修改模型位置不会覆盖实体。声音的位置参数也统一传递现有地面 `Vector3`，声源保留位置引用，监听器复用向量；距离衰减通过 `distanceToSquared()` 计算，不拆分 XZ 坐标或开方。用 `c_spawn("log")`、`c_spawn("butterfly")` 或 Shift + 右键丢弃物品可验证原有交互，`c_save()` 导出当前实体位置，读档恢复；抛落高度仍是视觉偏移。命令语法、参数和支持的 prefab/item ID 不变，详见 [地面坐标的权威来源](docs/inventory-architecture.md#地面坐标的权威来源)。

物品栏右键参考 Lua `widgets/invslot.lua:OnControl/DropItem/UseItem` 的分工：UI 将右键输入写入 input signal，读取 slot 的只读 `item` signal，并同步发布 `drop/use` 请求；应用验证物品实体后执行丢弃、进食、种花或背包装卸。连续右键分别处理，槽位投影更新不会重放动作；UI 断开和场景停止时释放对应订阅。`game:slot-context-menu` 仍跨 shadow root 冒泡；沿用网页已有的 Shift + 右键丢弃一个物品。`c_give`、`c_spawn`、`c_save` 的语法、参数和支持 ID 保持不变。

世界时钟直接读取世界 signal，已删除 `setClock()` 状态转发接口。 `createEffect` 直接导出实现，移除仅转发的包装层；普通 effect 的微任务调度、memo／世界信号桥接的同步结算和订阅清理行为保持不变。指针和日期仍每 60 个活动帧结算刷新；装饰动画逐活动游戏帧播放，暂停时停止，不累计第二份世界时间。以下调试命令的语法、参数和支持 ID 不变。

建筑容器面板的开关与屏幕定位由 `packages/ui/src/chest-inventory-panel.ts` 负责；`src/registerDisposal.ts` 创建面板、动作控制器、库存接收动画订阅、表情轮盘和右键菜单订阅，统一注册帧更新与场景内显式释放。`src/main.ts` 只注入依赖，在场景加载后完成注册；容器面板的帧回调也随释放移除。调试命令的语法、参数、行为和支持 ID 不变。

`c_save()` 会先结算尚未满 60 帧的昼夜／温度时间，再把当前季节温度、昼夜温度和噪声时间保存到 `world.systems.worldtemperature`，读档后继续计算。昼夜、季节和月相使用 `packages/signals` 导出的全局唯一单例 `clockstate`、`seasonstate`、`moonphasestate`，读档恢复现有单例的值，月相按累计游戏时间和现有 20 天周期恢复。`DstLightingRenderer` 用 `createEffect` 读取三个 signal 更新光照，不复制它们的状态；夜晚且月相为 `full` 时显示满月光照。旧存档缺少温度字段时，使用存档季节（默认春季）的中点温度，并以已保存的累计游戏时间初始化噪声时间。当前季节仍需显式修改 signal，尚未自动推进；这里保存的是环境温度，HUD 的角色体温尚未接入。`c_save()` 无参数，命令语法和支持 prefab/item ID 不变。

`c_spawn("cookpot")` 生成烹饪锅；`c_give("twigs", 4)` 准备四份树枝，或用 `c_give("twigs")` 与 `c_give("red_cap", 3)` 准备树枝和红蘑菇。靠近并点击锅，把材料放入四个格子；烹饪按钮按 Lua `containers.lua` 只检查容器是否装满，原料由容器按 `cooking.IsCookingIngredient()` 限制。UI 提交 `COOK` 请求，动作检查正在烹饪、其他开启者和满容器状态，再调用锅自己的 `stewer.StartCooking()`：读取真实原料实体，计算配方与时间，关闭容器、销毁原料并禁止打开。`main.ts` 只接入通用容器与动作服务，不保存锅列表、判断配方或扣材料。`packages/componets/src/cooking.ts` 与 `preparedfoods.ts` 按源 Lua 定义食材标签、别名和 68 条普通料理；不再限定最终产物为 `beefalofeed`。四根树枝和树枝加三个红蘑菇约 10 秒后得到蒸树枝；一根树枝、两个红蘑菇和一份怪物肉按更高优先级得到肉串。锅内食物按 recipe 的 `overridebuild`、`overridesymbolname` 和 `potlevel` 选择原版图层，完成时播放 `cooking_pst → idle_full`。`c_save()` 保存产物、剩余烹饪时间、原料记录、身份、位置及锅皮肤；读档和清洁扫把换肤保留组件与状态，兼容已有蒸树枝存档。完成后左键点击锅采收；装备锤子或清洁扫把时右键仍执行工具动作。玩家自动走近锅的地面脚点，按原版 `HARVEST → dolongaction` 播放 `build_pre → build_loop`，1 秒后交付配方产物，再播放 `build_pst`；配方的产出数量保留（如糖豆为 3 份）。移动、跳跃、Esc、点击其他目标或开始其他动作取消未提交的采收，食物仍留在锅内。采收成功播放空锅动画和关闭声、清除 `donecooking` 并允许重新打开；库存包先填充可用物品槽和堆叠，放不下的余量落在玩家脚边，预先准备美术后同步提交，因此立即 `c_save()` 也能保存。采收后的空锅身份、位置、皮肤及库存/地面产物身份、数量随保存与读档保留。锅内腐败、食材新鲜度传递、食谱学习和厨师专属配方仍待实现。命令语法、参数及支持的 `c_give` / `c_spawn` ID 不变。

建筑和建成墙的 `skinId` 使用 signal，`reskinTargets.prepareNextSkin()` 先准备原版资源，成功提交时设置皮肤 signal。表现订阅替换美术、保留动画进度与地面脚点，并释放旧资源；根实体、容器、烹饪组件及墙的血量、战斗和敲击组件保持不变。墙的皮肤准备只创建美术资源，皮肤初始化映射由 `packages/animation/src/prefabskin.ts` 的 Lua 对应函数提供，包括共享 build 的 alternate 皮肤。取消准备、加载失败或移除实体不改变皮肤，准备资源只释放一次；保存读取当前 signal。用 `c_give("reskin_tool")` 装备清洁扫把后，按现有换肤方式操作建筑和墙，并可用 `c_save()` 保存选中的皮肤。命令语法、参数和支持 ID 不变。


地图面板（按 `M` 或点击地图按钮）使用原版 `levels/tiles/map_edge.tex/xml` 的全部 48 个边缘遮罩，根据地皮八邻域选择直边、转角和组合形状；海洋先绘制，陆地按源地皮层顺序叠加，岸边允许伸入海洋格。`minimap.ksh` 的 RGB 乘噪声规则保留图集 alpha，噪声按世界坐标连续重复；挖地或耕地后重新生成地图纹理，`c_save()` 读档后由保存的地皮重建边缘。调试命令语法、参数和支持的 `c_spawn` / `c_give` ID 不变。

玩家创建时按 `player_common.lua` 初始化 `MiniMapEntity`：图标为角色名加 `.png`，优先级 `10`，`SetCanUseCache(false)`，`SetDrawOverFogOfWar(true)`。当前玩家使用 Maxwell 的原版可玩角色 build `waxwell`（`anim/waxwell.zip`），沿用共享 `wilson` 动画 bank；地图显示 `minimap/minimap_data2.xml` 中的原版 `waxwell.png`。物品栏“查看角色”按钮按玩家的美术角色 ID 读取 `bag/self_inspect_${player}.tex.png`，当前为 `self_inspect_waxwell.tex.png`；`DstInventoryBarElement.player` 属性或 `player` HTML 属性改变时直接更新图标，槽位和鼠标持有物不受影响。PNG 从原版 `images/hud.xml`／`hud2.xml` 与对应 KTEX 图集导出，可用 `pnpm --filter @dontstarve-web/ui self-inspect:import` 重新提取，`self-inspect:check` 校验全部 21 个原版图标。此次按请求替换美术，属性、角色能力及存档结构继续使用已有玩家实现。地图图标独立于地形缓存，每次绘制读取玩家现有位置，移动、缩放和拖动后重新投影；配置由角色初始化恢复，无需额外存档字段。迷雾系统尚未接入，已保留原版的跨迷雾显示标志。`c_save()` 和已有调试命令语法、参数及支持 ID 不变。原版两页地图图标资源可通过 `pnpm --filter @dontstarve-web/prefab minimap-icons:check` 校验。

猪王与地面背包也提供 `MiniMapEntity`：猪王使用原版 `pigking.png`、优先级 `1`，背包使用 `backpack.png`。地图从场景实体注册表读取实时图标列表；`c_spawn("backpack")` 生成后显示，拾取／装备／鼠标持有时按库存归属隐藏，丢弃后恢复。背包图标属于物品实体，换肤或替换美术不重建图标；`c_save()` 保存的猪王与背包身份、位置及物品状态在读档后重建对应图标。同时补齐 `c_spawn("backpack")` 的注册，可在玩家脚下生成可拾取的背包；`c_give("backpack", count)` 与其他命令的语法、参数保持不变。

在游戏页面按反引号键（`Backquote`，通常与 `~` 共用）打开或关闭调试控制台，输入命令后按 `Enter` 执行。执行后控制台自动关闭；`Esc` 可关闭，`↑` / `↓` 可浏览最近 50 条历史命令。执行结果或错误显示在浏览器开发者工具的 Console 中。

`src/InputManager.ts` 使用 signal 保存按键状态，`isManualMovement` 通过 `createMemo` 判断 WASD，`isActionInterrupting` 包含 WASD 与 Space，供动作控制器共用。重复按键不重复发布状态；调试控制台等输入框（包括 shadow DOM 内的输入框）不会触发移动，窗口失焦或表情轮盘切换时清空按键，输入管理器的 `dispose()` 用于页面内显式释放监听和 memo；`pagehide` 不执行资源清理。调试命令语法、参数和支持 prefab/item ID 保持不变。

`c_give("heatrock", count)` 获取暖石，`count` 为数量、默认 1；每块占一格，不能装备。`c_spawn("heatrock")` 在玩家脚点生成可拾取暖石。使用原版 `anim/heat_rock.zip` 的 bank/build `heat_rock`，初温为世界温度，地面动画和库存图标按相对环境温度切换 1～5 档，阈值为 −30、−10、10、30°C，等于阈值仍属于较低档。暖石的冬季／夏季固有保温均为 120，离开冰箱后按环境和附近热源升降温，排除其他暖石；放入冰箱后每游戏秒降低 1°C，常温环境最低 0°C，负温环境最低 `max(-20, 环境温度)`。初始耐久 100，从最冷／最热档自然返回常温档消耗 12.5，耗尽后移除。装备 `c_give("reskin_tool")` 获取的清洁扫把，右键地面暖石可按 `heatrock_fantasy`、`heatrock_fire`、`heatrock_planet`、默认外观循环换肤，使用各自原版动态 build 和当前温度档位的实际 atlas 图标。拾取、丢弃、转移、换肤及 `c_save()` 保存读档保留身份、数量、位置、皮肤、连续温度、耐久及温度循环的最高／最低记录；读档不额外扣除耐久。角色体温及暖石热光照尚未接入，命令参数和支持 ID 不变。

`c_spawn("poop")` 在玩家脚点生成一份便便，`c_give("poop", 3)` 给予三份。地面便便（包括皮弗娄牛定时生成的便便、丢弃和读档恢复）会附带原版 `anim/flies.zip` 的苍蝇子实体：`swarm_pre → swarm_loop` 配独立的 `dontstarve/common/flies` 循环声。玩家进入 2 个 DST 单位（场景 6）内时播放 `swarm_pst` 并停声；离开 3 个单位（场景 9）后重新出现并恢复声音，不要求夜间。拾取、燃烧或移除便便会移除苍蝇并取消其计时和音源；苍蝇是 `NOCLICK/DECOR`，不扩大便便的拾取目标，也不单独入档。`c_save()` 保留便便的身份、位置、数量，读档按当前位置重新建立苍蝇和邻近检测。便便没有原版皮肤；命令语法、参数和支持 ID 不变。


`c_give("razor")` 获取剃刀，`c_spawn("razor")` 在玩家脚点生成地面剃刀；剃刀每格一件、不可装备，也没有耐久。地面美术使用原版 `anim/razor.zip` 的 bank `razor` 与 `anim/swap_razor.zip` 的 build，物品栏图标取自 `inventoryimages.xml` 的 `razor.tex`；三款原版皮肤 `razor_barber`、`razor_scissors`、`razor_straight` 可用 `c_give("reskin_tool")` 的清洁扫把右键地面剃刀循环换肤，身份与位置保持。`c_spawn("beefalo")` 生成的皮弗娄牛现在按 `beard`、`sleeper` 组件工作：夜间由 sleeper 每 4 ± 0.5 秒（游戏时间）检测并入睡，天亮后同样周期检测醒来。左键点击物品栏里的剃刀，让它被鼠标举着，再左键点击牛：玩家走近后进入 `shave` 状态（`build_pre → build_loop`，循环声 `dontstarve/wilson/shave_LP`），1 秒后提交 `SHAVE`。牛醒着时状态以 `AWAKEBEEFALO` 拒绝，胡须为零时以 `NOBITS` 拒绝，鼠标上的剃刀都保持不变；牛睡着时掉落 3 份 `beefalowool`、换成 `beefalo_shaved_build` 并播放 `shave`，之后继续睡，醒着则播放 `sleep_pst`。毛量按 `beard` 的 `daysgrowth` 回调，剃光后第 3 天的 `OnHairGrowth` 让牛在下次进入待机时依次播放 `hair_growth_pre`、`hair_growth`，恢复 3 份毛；`bits`、`daysgrowth` 是组件私有 signal，`has_beard` 标签和 `beefalo_build` / `beefalo_shaved_build` 外观都由 `beard.hairy` memo 派生，详见 [DST 事件与 signal 映射](docs/dst-event.md#beefalo胡须与睡眠)。`c_save()` 保存牛的 `components.beefalo.beard`（`growth`、`growthaccumulator`、`bits`），读档按 `beard.lua:OnLoad` 重放日回调，已剃光的牛直接显示剃光外观；鼠标上的剃刀随 `player:cursor/0` 保存恢复，缺少 `beard` 字段的旧存档按满毛加载。刷毛 `brushable`、驯化 `domesticatable`、牛铃 `beefbell` 和皮肤 `skinner_beefalo` 尚未移植，所以剃毛暂不改变顺从度。命令语法、参数不变，新增 `c_spawn` / `c_give` ID：`razor`。

`c_give("panflute")` 获取排箫，`c_spawn("panflute")` 在玩家脚点生成地面排箫（4 款原版皮肤 `panflute_an`、`panflute_harlequin`、`panflute_insect`、`panflute_swamp` 可用清洁扫把换肤）。右键物品栏中的排箫触发 `PLAY`：玩家进入 `play_flute` 状态（`action_uniqueitem_pre → flute`，`pan_flute01` 符号换成 `pan_flute` build 或皮肤 build），第 30 帧提交动作、播放 `dontstarve/wilson/flute_LP`（`wilson.fsb` 流 81–87）并消耗 1 次耐久（共 10 次）；第 52 帧起可打断。`instrument` 组件向 15 范围内的 `sleeper` 调用 `AddSleepiness(10, 20)`：睡眠抗性 3 的皮弗娄牛立即入睡，20 秒后才开始醒来检测。骑乘、Wortox 技能/增益、农作物照料、`grogginess` 与 `knockedout` 分支尚未移植；耐久用尽时按 `tool` 组件触发 `toolbroke`。

`c_give("lantern", count)` 获取满燃料提灯，每盏占一格；`c_spawn("lantern")` 在玩家脚下生成已点亮的提灯。燃料与开关按 `prefabs/mininglantern.lua` 的 `fueled` / `machine` 组件挂在物品实体上：满燃料 `TUNING.LANTERN_LIGHTTIME = (night_time + dusk_time) × 2.6 = 468` 秒；装备时有燃料就开灯，卸下或放入物品栏关灯，掉在地上关灯后再开灯；只有开着时耗油。开灯按 `SetFirstPeriod` 额外扣一次首段燃料（满燃料 1/60 秒，否则 0.5 秒）。燃料每 60 个活动帧结算一次，转移、丢弃、拾取和 `c_save()` 前结算未满一批的部分。光照半径和亮度随燃料百分比从 3→5、0.4→0.6 插值，并从同一实体的开关与燃料 signal 派生。与火把不同，燃料耗尽只关灯，提灯以 0% 燃料保留在手上、物品栏或地面，并以 `remainingFuel: 0` 保存；空提灯补充燃料后可重新点亮。地面提灯另存 `lantern: { ison }`，读档时按 `machine:OnLoad` 恢复开关（旧存档缺少该字段时视为开启）。已支持荧光果 `lightbulb` 添加 `CAVE` 燃料（用法见下文）。尚未实现手动开关、开关音效与循环音效，以及耗尽时的 `torchranout` 自动换装。

手部装备变化在库存事务成功提交后发布到 `handEquipmentExistenceState`，同时携带对应的物品实体引用。[packages/signals](packages/signals/README.md) 提供 `createEquipmentExistenceState('HANDS')` 工厂，每个 `InventoryStore` 默认创建独立实例，也可通过构造函数第五个参数的 `{ handEquipmentExistenceState }` 对象注入；`InventoryStore.handEquipment` 是该实例的只读接口。应用通过 `bindPlayerHandEquipment({ handEquipmentExistenceState, owner, ... })` 显式传入同一实例和装备者。存在状态只表示当前装备身份，不是移除请求，不表示燃烧状态或燃料数量。先在 `src/playerHandEquipment.ts` 注册订阅，再由 `InventoryStore.replaceState()` 恢复存档并写入 signal；该次写入直接触发装备生命周期和手持动画，订阅注册时不回放当前值。后续变化通过 prefab 注册表依次执行旧装备 `onunequip()`、新装备 `onequip(owner)`，并接入手持外观、照明和光标。`main.ts` 只接入订阅器的帧更新、结算、成功转移动画和释放。燃料及其他库存更新不重新发布装备。torch 通过独立的 `burning` signal 同步照明，`extinguish()` 只停止燃烧，保留装备和剩余燃料；燃尽时 torch 先 `entity.remove()`（库存 owner 清空手部槽，对应 Lua 的 `inst:Remove()`），再向 owner 推送 `itemranout`，玩家自动装上背包里的下一把同 prefab 火把。`onunequip()` 和释放停止燃烧并释放 owner，不修改槽位值。地面火把没有 owner，熄灭不会修改玩家装备。正常卸下使用库存转移。signal 不写入存档；UI 操作、命令及读档仍由库存提交装备结果。

头部和身体装备采用相同的工厂与订阅流程：`createEquipmentExistenceState('HEAD')` / `createEquipmentExistenceState('BODY')` 创建每个库存独立的 `headEquipmentExistenceState` / `bodyEquipmentExistenceState`，Store 在装备事务成功提交后发布身份。`src/playerHeadEquipment.ts` / `src/playerBodyEquipment.ts` 在读档前注册订阅，帽子与背包外观、背包面板开关和材料可访问性都由 signal 更新驱动；不再通过 `syncHeadEquipment()` / `syncBodyEquipment()` 读取库存同步。三种绑定共用 `src/playerEquipment.ts` 的生命周期切换与释放逻辑。普通物品或组件更新不重新装备，正常卸下仍保留物品；装备耗尽由对应 prefab 移除自己的实体，结果随 `c_save()` 保存恢复。

`c_give("lightbulb", count)` 获取荧光果（默认 1，每叠最多 40 个），`c_spawn("lightbulb")` 在玩家脚点生成发光的地面荧光果；也可用 `c_spawn("flower_cave")` 生成灯草并左键采集。荧光果按 `PERISH_FAST` 保鲜 6 个游戏日（2880 秒），沿用每 10 个游戏秒结算、转移／进食／保存前结清的规则；地面腐败速率为 1.5 倍，温度和受潮倍率由通用 perishable 组件处理。右键物品栏荧光果执行进食：鲜食回复 1 生命，不增加饥饿或理智；陈旧时回复 0.333 生命，变质时不回复生命并损失 10 理智；完全腐烂后整叠替换为 `spoiled_food`。

左键拿起荧光果后，点击物品栏或手部装备槽中的提灯，或左键点击地面提灯，执行通用 `ADDFUEL` / `ADDWETFUEL`；地面目标超出 4 个场景单位时先走近。`pickup → pickup_pst` 第 6 帧成功提交时消耗一个荧光果，补充 90 秒燃料（受潮时 67.5 秒），燃料上限 468 秒，满燃料仍会接受并消耗燃料。提交前取消、目标被转移／移除或荧光果腐烂不会消耗；装备着的空提灯补燃料后自动开启，物品栏和已关闭的地面提灯保持关闭。`c_save()` 无新增参数，保留荧光果身份、数量、新鲜度、受潮与地面位置，以及提灯身份、皮肤、剩余燃料和地面开关，读档恢复；例：`c_give("lightbulb", 4); c_give("lantern"); c_spawn("lightbulb"); c_save()`。

采集等长动作的“刷刷”声随 `build_loop` 动画每一圈触发一次原版双层短音效，不再以约 0.11～0.18 秒的样本时长连续循环；准备、结束及取消后的动画不继续重复。成功采下灯草时另播放一次 `pickup_lightbulb`，与灯草 `picking → picked` 姿态同步。

手部 signal 的非空值必须声明 `EQUIPSLOTS = "HANDS"`，同时受 TypeScript 类型和 setter 运行时校验限制；身体装备或缺少槽位声明的对象不能写入。torch 公开只读的 `EQUIPSLOTS: "HANDS"` 属性。`c_give`、`c_spawn` 和 `c_save` 的命令参数及支持 ID 不变。

火把点燃播放原版 `dontstarve/wilson/torch_swing`（两段样本随机选择），卸下、燃尽或成功拾取正在燃烧的地面火把时播放一次 `dontstarve/common/fireOut`。`OnPutInInventory()` 恢复 `idle`、停止燃烧与地面音源，保留剩余燃料和皮肤；普通未点燃火把拾取不播放熄灭声。地面实体接收 `onextinguish` 事件后调用 `OnExtinguish()`：熄灭照明、恢复 `idle`，按 Lua 的小范围随机水平速度和向上速度弹离地面，保留燃料、实体 ID 与皮肤，不修改玩家手部装备。声音在装备或生成前预加载，真实鼠标或键盘输入恢复音频上下文。

地面燃烧状态保存到 `ground_item.components.torch.lit`，剩余燃料仍保存在 `stack.remainingFuel`；换肤保留燃烧和最新燃料，读档恢复燃烧但不重播点燃声。`c_spawn("torch")` 和普通丢弃仍生成未点燃火把。当前接入这两个回调及地面照明/弹跳，不包含投掷输入、飞行/插地动作、雨水/技能修正及原版火焰粒子；外部游戏逻辑可通过地面模型的 `userData.torch.ignite()` 点燃，通过 `onextinguish` 事件熄灭。

装备 `torch` 后，鼠标悬停可燃建筑显示右键“点燃”，右键自动走近地面脚点并执行原版 `LIGHT → catchonfire`：播放 `light_fire` → `light_fire_pst`，第 13 帧调用火把的 `lighter` 和目标的 `burnable`，不额外扣除火把燃料。当前可燃建筑为木箱 `treasurechest` 和烹饪锅 `cookpot`；例如执行 `c_give("torch");c_spawn("treasurechest");`，或 `c_spawn("cookpot")`，再把火把装备到手部槽并右键建筑。移动、跳跃、Esc、更换装备或操作其他目标会取消未提交的点燃；燃料耗尽、目标移除或已经燃烧时不能提交。

木箱燃烧 10 秒、锅燃烧 20 秒，使用 `anim/fire.zip` 的 `level2` / `level3` 原版火焰、局部照明及独立循环火声；附近已接入燃烧组件的建筑和地面物品按原版热量传播和阴燃分支受热。建筑、草丛／树苗、可燃地面物品和矮星的传播半径按当前季节派生：春季乘原版 `SPRING_FIRE_RANGE_MOD = 0.67`，其他季节使用基础半径；邻居查询与距离热量衰减共用修正后的半径。季节切换不重启传播定时器，下一次 0.5 游戏秒传播更新读取新半径。烧毁后显示原版 `burnt` 残骸、掉出容器中的真实物品，锅掉出已有料理并停止烹饪；残骸不能打开，再锤击一次即可拆除。建筑提供只读 `userData.burningSignal` 和 `userData.burntSignal`，火焰表现和容器 UI 订阅状态更新，烧毁主动关闭已打开的面板；换肤保留根实体、组件、signal、位置和燃烧进度，移除实体或关闭面板时释放订阅。`c_save()` 按原版将正在燃烧或已烧毁的建筑保存为 `building.burnt: true`，读档直接恢复残骸，保留实体 ID、位置、皮肤以及掉出物品的身份、数量和组件状态。当前接入这些建筑和下述材料的普通点火、烧毁及干燥天气传播分支，其他植物/物品、雨水和角色技能修正仍未接入。命令语法和参数不变；材料新增的 `c_spawn` 入口见下文。

地面上的干草 `cutgrass`、木头 `log` 和草簇 `dug_grass` 同样支持手持 `torch` 右键点燃。可执行 `c_give("torch");c_spawn("cutgrass");`，装备火把后右键地面干草；`c_spawn("log")` 生成木头，也可将 `c_give("cutgrass", 3)` / `c_give("log", 7)` 得到的物品丢到地上再点燃。干草燃烧 7.5 秒、木头燃烧 15 秒、草簇燃烧 30 秒，整叠烧毁后在原脚点生成同数量的一叠灰烬 `ash`（原版上限 40），原物品移除；灰烬美术提前准备，烧毁后立即 `c_save()` 即可保存灰烬实体、位置和数量并读档恢复。物品通过只读 `burningSignal`、`burntSignal` 和 `persistenceSignal` 通知表现及存档状态。正在燃烧时不能拾取，按原版 `DefaultBurnFn` 不写入存档；熄灭后重新可保存、可拾取，身份、数量和已有组件状态不变，拾回再丢弃保留同一份燃烧组件和 signal。活木 `livinglog`（`c_spawn("livinglog")` / `c_give("livinglog", 3)`）同样可被火把点燃并燃烧 15 秒、烧成灰烬：按 `livinglog.lua` 的 `onignite` 在点燃瞬间播放 `dontstarve/creatures/leif/livinglog_burn`（`leif.fsb` 四个样本随机选一），燃烧期间沿用通用火焰与循环火声；读档恢复燃烧不重播惨叫。石头等未声明燃烧组件的物品不提供“点燃”。新增 `c_spawn("cutgrass")`、`c_spawn("log")`、`c_spawn("ash")`，均生成在玩家脚点；`c_give` 已支持这三个 ID，语法与数量参数不变。

原版 Lua 中哪些 prefab 可用 `c_spawn`、哪些可通过 `c_give` 入栏，见 [prefab 命令静态核对表](docs/dst-prefab-console.md)。该表记录源码调查结果；本项目当前支持的 ID 以本文下方对象列表及物品定义为准。

`c_give("alterguardianhat")` 获取启迪之冠，拖到头部装备槽后按玩家真实理智判定：严格高于 85% 才播放 `activate_pre → activate_loop` 的漂浮前后层并提供局部光；Wilson 为 171/200 时激活，170/200 时不激活。理智降至 85% 或以下时立即移除光源并播放 `activate_pst`，第 8 帧恢复普通帽子外观；升回阈值以上则重新激活。创建玩家时注入 `playerStats.sanity.percent` 只读 signal，帽子的激活 memo 直接读取它，随 `c_setsanity`、食物和装备效果更新，不复制理智状态；卸下、更换为普通帽或显式场景销毁时解除依赖，异步加载帽子期间改变理智也采用最新值。默认外观和 `alterguardianhat_lastprism` 共用此规则。可用 `c_setsanity(0.85)`、`c_setsanity(0.855)` 验证边界。`c_save()` 保存理智和帽子的身份、数量、皮肤与装备位置，读档按保存的理智重新判定，不保存或沿用旧激活状态。命令语法、参数和支持 ID 不变；孢子／月种子容器、感应月狂与攻击召唤虚影仍未移植。

低理智滤镜使用原版 `images/colour_cubes/insane_day_cc.tex`、`insane_dusk_cc.tex` 和 `insane_night_cc.tex`，按昼夜与季节调色同步渐变。调色将理智比例四舍五入到最近的 10% 档位（0%、10%、…、100%），再按 `colourcube.lua` 的平方曲线计算 `(1 - 档位比例)²`；例如 `c_setsanity(0.175)` 保留理智 35/200，调色按 20% 计算，强度为 0.64；`c_setsanity(0.149)` 按 10% 计算，强度为 0.81。原版 Lua 的曲线未作这种分档。世界画面边缘按 `postprocess_distort.ksh` 晃动，速度和幅度仍使用实际理智比例，速度为原版扭曲系数 `1` 时的一半，中心保持稳定；HUD 不受滤镜影响。旧存档未提供理智时沿用状态栏的 35/200，`c_setsanity(1)` 可恢复满理智画面。 `playerStats.sanity` 是工厂创建的理智点数 signal，可通过 `set(value)` 更新有限数值并自动限制在 0 到 200；`percent` 是同一状态的只读比例视图。滤镜在创建时接收并订阅该视图，状态栏独立订阅理智变化；直接写入 signal 也会更新两处，调试命令无需手动刷新。保存通过 `getPlayerStats()` 导出纯数值快照，读档先创建 signal，再初始化滤镜；滤镜 `dispose()` 用于页面内显式释放订阅及渲染资源；`pagehide` 不执行清理。

调色资源由 `src/main.ts` 显式调用 `DstLightingRenderer.create()` 并行加载，完成后通过 `game:lighting-ready` 事件发布实例，`src/universal.ts` 接收后供场景使用。场景在事件完成后启动；加载失败会中止启动。单独导入 `universal.ts` 不会请求调色资源或读取存档。




`c_give("bernie_inactive")` 获取伯尼，数量可指定为 `c_give("bernie_inactive", 2)`，每只占一格。Shift + 右键物品槽放到地面，也可用 `c_spawn("bernie_inactive")` 直接在玩家位置生成。地面形态按玩家实际理智比例切换：低于 15%（Wilson 理智低于 30/200）显示 `bernie_big`，其余显示 `bernie_active`；`c_setsanity(0.1)` 和 `c_setsanity(0.175)` 可验证两种形态。变大播放大伯尼的 `activate`；变小依次播放大伯尼的 `deactivate`、`deactivate_pst` 和小伯尼的 `activate`。起身结束后先播放 0.5 秒 `idle_loop_nodir`，保留播放时间切回 `idle_loop`。变身期间再次改变理智，会在当前动画流程完成后按最新理智切换。使用原版 `bernie.zip` / `bernie_big.zip` 动画和共享 `bernie_build.zip`，大伯尼保持 Lua 的 0.7 缩放，支持艾希莉、小火花两种皮肤。点击任一形态拾回时立即取消动画，仍为 `bernie_inactive`；位置、实体 ID、皮肤和物品数量随 `c_save()` 保存，恢复时根据玩家理智直接显示待机形态。当前按请求让 Wilson 也能触发两种地面形态，实现待机、大小切换动画与拾取，不包含原版 Willow 限制、技能、跟随、战斗、耐久和变身冷却。

`c_spawn("tumbleweed")` 在玩家脚点生成风滚草，无额外参数，不能 `c_give`。美术使用原版 `anim/tumbleweed.zip`（bank/build `tumbleweed`，四面朝向按摄像机航向选取，`move_loop` 循环）。世界新增 `worldwind` 组件（`packages/componets/src/worldwind.ts`）：`angle` 是私有可写 signal（初始 0～360 随机整数，对外只读），`windchange` 是只读 signal，每次变风都发布一个新的 `{angle, velocity}`（即使角度重复也通知）；风速恒为 1。首次变风在 1 个游戏秒后，之后每 15～30 秒（`0.5～1 × SEG_TIME`）由游戏时间调度器上的离散任务触发，不逐帧递减；风向不入档，读档重新随机。风滚草按 `blowinwind.lua`（`packages/componets/src/blowinwind.ts`）滚动：生成时读取当前风向并加 ±10 度随机偏差（限制在 0～360），监听 `windchange` 后同样加偏差更新方向；风向向量逐帧累加为速度（上限 1），速度映射到平均行走速度 5 DST 单位（场景 15），速度大于等于 0.5 后按正弦在 0.5～1.5 倍间变化，沿 `(cos, -sin)` 前进，与原版一致。左键点击执行 `PICK`（`dolongaction`），长动作开始时推送 `startlongaction`：风滚草停下并播放 `move_pst → idle`，2～6 秒后 `move_pre → move_loop` 重新滚动。采摘按原版权重表抽取 3 件战利品掉在原地并播放 `break` 特效，风滚草不进入物品栏。每约 0.8 秒检查脚下是否仍是陆地，滚到海里会被移除。`c_save()` 只保存身份和位置（原版只在燃烧时存 `burnt`），读档按当前风向重新滚动。战利品表中 `foliage`、`trinket_*`、`blueprint`、`beardhair`、`cookingrecipecard`、`scrapbook_page` 已有地面美术，会按权重掉落；`rabbit`、`spider`、`frog`、`bee`、`mosquito` 项目尚无 prefab，仍参与抽取但不会掉落；燃烧／灰烬、弹跳与合唱音效、幽灵作祟、玩家靠近事件尚未接入。

`c_give("goldnugget")`、`c_give("meat")`、`c_give("pigskin")`、`c_give("bird_egg")` 等带 `tradable.goldvalue` 的物品可交给猪王（物品栏拿起后点击猪王）：猪王播放 `cointoss`（第 17 帧 `PigKingThrowGold`）→ `happy`（第 6 帧 `PigKingHappy`），2/3 秒后向交易者方向抛出与 `goldvalue` 等量的金块，物品被消耗。`goldvalue` 为 0 的物品（如 `monstermeat`、`humanmeat`、`barnacle`）会被拒绝，猪王播放 `unimpressed` 与 `PigKingReject`；没有 `tradable` 组件的物品（如斧头）不能给予。夜晚猪王进入 `sleep`（`sleep_pre` → `sleep_loop`）并禁用 trader，天亮播放 `sleep_pst` 后恢复；睡觉与交易状态不写入存档，加载后按当前昼夜重新判定。猪王位置随 `c_save()` 保存。未移植 `pig_token` 小游戏、万圣夜糖果和 `tradefor`（目录中没有物品设置它）。




### c_spawn 支持的对象

`c_spawn("mole")` 在玩家脚点生成鼹鼠；`c_give("mole", count)` 给予活鼹鼠（数量为正整数、默认 1，每只单独占一个槽位）；`c_spawn("molehill")` 生成鼹鼠洞，无额外参数，洞穴不能 `c_give`。例如 `c_spawn("mole");c_give("rocks",3);c_give("hammer");c_give("shovel")`。鼹鼠使用原版分离的 `anim/mole_basic.zip`（bank `mole`）和 `anim/mole_build.zip`，地下移动特效使用 `anim/mole_move_fx.zip`，库存图标由导入器解析实际 atlas；原版没有鼹鼠皮肤。

按 `molebrain.lua` 和 `SGmole.lua` 地下行走（2.75 DST 单位/秒）、每 15～25 游戏秒探头、在 20 DST 单位内寻找有 `molebait` / `bait` 的矿物与玩具，并在偷取动画第 12 帧由诱饵的 `onstolen` 转移真实实体（保留 ID、数量和状态）；目标被拾走或燃烧时取消。携带库存为 3 槽，无洞时先等待两段 5～10 秒延迟，在 5～15 DST 单位的可行走陆地寻找新洞；白天、库存满或同伴遇袭时回巢，将库存转入洞穴的 50 槽库存。洞穴在白天排队，黄昏／夜晚延迟 5～20 秒放出同一只鼹鼠，子代死亡或被捕后按原版 1200 游戏秒补生。 世界阶段统一为从 `clock.phase` 派生的 `cycle`（`day`、`dusk`、`night`）；鼹鼠、洞穴和 Sleeper 各自通过 `WorldContentKey.Cycle` 创建私有监听。Mole 直接传入世界的 `getWatchWorldContent`，返回的本地 signal 带有同一世界的只读 `scheduler` 引用；Mole、Molehill 和 Sleeper 从返回值取得调度器，Sleeper 不再单独接收 scheduler 参数。共享实例由世界状态创建、按游戏时间推进并在世界释放时销毁，组件清理只取消自己的任务。Sleeper 自行创建和清理本地 signal：鼹鼠白天睡觉，黄昏／夜晚醒来。调试命令的语法、参数和支持 ID 不变。

装备锤子，在鼹鼠探头时按住 `Ctrl+F` 强制攻击，命中造成 17 点伤害并击晕；地下和击晕状态不可攻击。击晕时掉出携带物，4～8 游戏秒内可左键拾取；从库存丢出也会击晕，再寻找新洞。鼹鼠有 30 点生命，死亡掉落 `smallmeat`；只在库存内按 2 天基础时长变饿。把矿物拿到鼠标上再点库存中的鼹鼠执行 `FEED`：吃一件 ELEMENTAL 食物、按原版食物值恢复生命并重置饱腹度。支持昼间睡眠和排箫催眠；入睡第 1 帧停止嗅闻，睡眠第 27 帧播放原版音量和降调的短睡眠声（不循环原始样本）、第 42 帧停止，回巢／拾取后暂停状态图，避免隐藏实体继续发声。装备铲子右键洞穴执行 `DIG`，一次挖完，掉出储存物和按 4 / 1.5 / 0.5 / 1.5 权重抽取的 `rocks` / `nitre` / `goldnugget` / `flint`；在洞内的鼹鼠被释放并击晕。

`c_save()` 无参数，保存鼹鼠身份、脚点、生命、饱腹度、无家等待时间和携带物；洞穴保存位置、库存、洞内子代或洞外子代的引用，避免重复保存同一只鼹鼠。读档重建洞穴所属关系及补生任务，鼹鼠的暂态动画不入档。原版的冰冻、电击、陷阱／猫攻击和幽灵作祟交互尚未接入。

通过 `c_give` 获取工具或放置物品后，动作切换由共享的 `action:begin` / `action:interrupt` 事件通知各模块取消自身工作；选槽、制作和表情轮保留各自的打断范围。开始事件排除发起者，异步加载被打断后不再提交旧动作；`PICK` 在请求动作时发送开始事件，走近和资源准备均受同一取消机制管理。事件与清理规则见 [库存与动作接线](docs/inventory-architecture.md)。

`c_spawn("flower_cave")`、`c_spawn("flower_cave_double")`、`c_spawn("flower_cave_triple")` 生成单头、双头和三头灯草。按 Lua 的 `plant` / `pickable` 标签提供通用左键 `PICK` 动作；燃烧（`fire`）或 `intense` 状态不可采集。采集分别获得 1、2、3 个 `lightbulb`，灯草立即熄灭并播放 `picking` → `picked`；再生时间分别为 1440、2160、2880 游戏秒，再生后恢复 `pickable` 标签并开始充能。提交前取消或资源准备失败时保留灯草状态；库存满时产物通过共享 `GiveItem` 路径落地，采摘仍成功。`c_save()` 保存实体 ID、位置、外观变体、光照状态与采集后的剩余再生时间，读档后恢复相应标签和计时。

`c_give("fence_item", 6)` 获取木栅栏物品（每叠 20 个，对应 `fence.lua` 的 `STACK_SIZE_MEDITEM`），`c_spawn("fence_item")` 生成同一个可拾取的地面物品；`c_spawn("fence")` 在玩家前方的格子中心生成已建成的栅栏（旋转为 0，使用窄的 `fence_thin` bank）。`fence_item` 的库存图标为 `images/inventoryimages.xml` 的 `fence_item.tex`，地面使用 `fence/fence/inventory`；它可点燃并留下灰烬，尚未实现燃料用途。物品栏中左键 `fence_item` 进入放置预览：预览按 `MakePlacer(..., fixedcameraoffset = 0, "eight")` 相对相机放置，旋转为 `-相机 heading`，所以放置时栅栏总是正对相机；预览为 65% 不透明，格子吸附与墙相同（1 DST 单位），按 `CalcRotationEnum` 的奇偶选 bank——奇数用 `fence`（宽），偶数用 `fence_thin`（窄），旋转相机时预览随之切换。若紧贴一道与之平行的栅栏且朝向相反（从背面补洞），预览会旋转 180° 与邻居同向（`FixUpFenceOrientation`）。左键放置消耗 1 个物品并播放 `place_structure_wood`，右键取消。已建成的栅栏是八向动画实体：由 `rotation + 相机 heading` 选择 `facing` 掩码（DOWN=8、UP=2、左右共用 5、两组斜向共用 48/192），左右共用的 clip 面向左侧时水平镜像；旋转相机时已放置的栅栏随之换面，但保存的旋转不变。

将 `rock_avocado_fruit_sprout` 拿到鼠标后右键种植：原版 placer 使用 `rock_avo_fruit_master/idle_buried_seed`（动画来自 `rock_avocado_fruit.zip`，build 为 `rock_avocado_fruit_build`），默认 2 DST 单位间距，提交 `DEPLOY` 后只消耗 1 个芽并播放 `plant_tree`。世界幼苗 ID 为 `rock_avocado_fruit_sprout_sapling`，也可直接 `c_spawn`，不能 `c_give`。幼苗不受冬季停长或春季倍率影响，经过 1500 游戏秒后播放 `seed_growth`，动画时长结束时由游戏时间调度器替换成原生石果灌木（随机 1–4 阶段，无需移植施肥），并播放 `treeGrow`。铲挖幼苗返还 1 个芽并取消所有生长／破土任务；点燃时取消生长计时，熄灭后重新从 1500 秒计时，燃烧 7.5 秒后留下灰烬。按源码，生长计时的剩余时间和暂停状态写入存档，破土动画进度不保存；生长计时已取消／结束时读档重新登记 1500 秒。

石果灌木燃烧 20 游戏秒后变灰，成熟石果保留为 3 个掉落物；燃烧中的灌木仍可存档，读档立即结算烧毁。`c_save()` 保留灌木／幼苗 ID、脚点、生长阶段与剩余时间、移植／采摘额度、枯萎恢复和防护状态，以及剩余硬壳石果、熟果新鲜度、石果芽和镐子的身份、数量或耐久。示例：`c_spawn("rock_avocado_fruit"); c_give("pickaxe"); c_give("rock_avocado_fruit_sprout", 2); c_save()`；灌木移植仍可用 `c_spawn("rock_avocado_bush"); c_give("shovel"); c_give("dug_rock_avocado_bush", 2); c_give("poop", 2)`。灌木世界实体不能 `c_give`。

`c_give("gunpowder", 5)` 获取火药（每叠 40 个），`c_spawn("gunpowder")` 在玩家脚点生成一份地面火药；库存图标为 `images/inventoryimages.xml` 的 `gunpowder.tex`，地面使用 `gunpowder/gunpowder/idle`，无原版皮肤。装备 `torch` 后右键地面火药执行通用 `LIGHT`：火药作为 `burnable` 点燃后带有通用火焰特效、`campfire` 与 `blackpowder_fuse_LP` 循环引信声，燃烧 3–6 游戏秒后整堆爆炸——播放 `explode_small`（`anim/explode.zip` 的 `small`）与 `blackpowder_explo`，并移除自身。爆炸对 3 DST 单位内的可工作物体执行 `WorkedBy(10 × 火药叠数)`（可入栏物品最多处理 20 件并按其叠数放大），因此硬壳石果会被整堆开采并散落产物；点燃范围内没有 `fueled` 的可燃物（原木、便便、熟石果、其他火药，火药可连环爆炸），并向范围内实体推送 `explosion` 事件。未被开采而幸存的硬壳石果由事件弹开。点燃后的火药不写入存档（`persists = false`），`c_save()` 保留未点燃火药的身份、数量与位置。当前未实现战斗伤害、`explosiveresist`、码头伤害和屏幕闪动。示例：`c_spawn("gunpowder"); c_give("torch"); c_spawn("rock_avocado_fruit"); c_save()`。

`c_spawn("berrybush")` 在玩家脚点生成普通浆果丛，使用 `anim/berrybush.zip` 的 `berrybush` bank/build。左键采摘获得 1 个 `berries`；浆果按剩余采摘额度显示 `berriesmost` / `berriesmore` / `berries` 三种层级，采摘播放 `picked → idle` 并在 `picked` 结束后隐藏果实，再生播放 `grow → idle`。原生浆果丛不消耗采摘额度；再生为 1440 秒 + 已消耗额度 × 240 秒 + 0–960 秒随机变化，春季登记新任务时乘 0.75，冬季暂停。登记后等待期间不重新抽取随机值，保存／读档保留剩余时间。浆果使用现有食品新鲜度组件。

装备铲子右键 `berrybush`：成熟健康植株掉落 1 个 `berries` 和 1 个 `dug_berrybush`，采摘后尚可再生的植株只掉落 `dug_berrybush`，缺肥或枯萎植株改掉两根独立 `twigs`。`c_give("dug_berrybush", 2)` 获取挖起的浆果丛，每叠最多 10 个，`c_spawn("dug_berrybush")` 生成可拾取地面物品；库存图标使用 `images/inventoryimages.xml`，地面使用 `berrybush/dropped`。拿到鼠标后右键种植，预览为 `dead`，默认间距为 2 DST 单位；沿用 `DEPLOY` 走近与第 6 帧提交，成功只消耗 1 株，位置无效或取消时保留物品。重新栽种后必须施肥：将 `poop`、`guano` 或 `spoiled_food` 拿到鼠标，左键缺肥植株“施肥”；恢复 4–5 次采摘额度，最后一次采摘后进入 `idle_to_dead → dead` 并停止再生。冬季施肥仍等待冬季结束。高温枯萎、肥料防枯萎次数、季节积雪和小型障碍碰撞沿用组件机制。

普通浆果丛支持 `reskin_tool` 的三款源皮肤：`berrybush_cawnival`、`berrybush_mystical`、`berrybush_swamp`；挖起后对应 `dug_berrybush_*`，皮肤库存图标使用各自实际 atlas。换肤保留植株 ID、脚点、当前动画和组件状态；挖取、拾取、丢弃、重新种植与 `c_save()`／读档保留对应皮肤。`c_save()` 同时保存采摘／移植／冬季暂停状态、随机采摘额度、剩余再生时间、防枯萎次数及恢复计时，恢复时不重播采摘动画。示例：`c_spawn("berrybush"); c_give("shovel"); c_give("reskin_tool"); c_give("poop", 2); c_save()`。世界浆果丛不能 `c_give`。本次范围为 `berrybush` 的采摘、生长和移植，不含 `berrybush2`、多汁浆果丛、采摘刷火鸡及节日／蜡制变体。

`c_spawn("monkeytail")` 在玩家脚点生成猴尾草，bank 为 `grass`（`anim/grass.zip`），build 为 `reeds_monkeytails`（`anim/reeds_monkeytails.zip`），库存物品 `dug_monkeytail` 使用 `dropped` 姿态与 `images/inventoryimages2.xml` 的 `dug_monkeytail.tex`，每叠最多 10 个，无原版皮肤。左键采摘获得 1 个 `cutreeds`，播放 `picking → picked` 与原版采摘声；基础再生 1440 游戏秒，春季新登记任务乘 0.75，冬季暂停，到期播放 `grow → idle`，原生植株不消耗移植次数。装备铲子右键挖取：成熟植株掉落 1 个芦苇与 1 个 `dug_monkeytail`，已采摘／缺肥植株只掉落挖起的猴尾草，夏季枯萎的植株改掉芦苇。

`c_give("dug_monkeytail", 2)` 获取猴尾草苗，`c_spawn("dug_monkeytail")` 生成可拾取地面物品。左键物品栏将草苗拿到鼠标，右键可种植地面栽种；原版 placer 使用 `grass/idle` 与猴尾草 build，沿用 `DEPLOY` 走近及 `doshortaction` 第 6 帧提交，成功消耗 1 株。海洋、硬地皮与过近位置拒绝种植，取消／失败保留鼠标物品。移植后显示 `idle_dead`，必须先施肥：`c_give("poop", 2)`、`c_give("guano")`、`c_give("spoiled_food")` 获取肥料，将肥料拿到鼠标后左键枯空植株“施肥”，第 6 帧消耗 1 个并恢复生长。每次施肥恢复原版随机 5–7 次移植采摘额度；耗尽后停止生长并需重新施肥，冬季施肥仍等待冬季结束。高温超过植株随机 70–94°C 阈值且未下雨时枯萎，低温／降雨后恢复；肥料提供有限采摘次数的防枯萎保护。装备火把可点燃，燃烧 15 游戏秒后留下灰烬。`c_save()` 保留植株 ID、脚点、采摘／移植／冬季暂停状态、剩余生长时间、采摘额度、防枯萎次数和枯萎恢复计时，也保存草苗／产物及鼠标物品的 ID、数量和位置；读档恢复对应姿态和任务。验证示例：`c_spawn("monkeytail"); c_give("shovel"); c_give("dug_monkeytail", 2); c_give("poop", 2); c_save()`。猴尾草世界实体不能 `c_give`。

`c_spawn("sapling")` 和 `c_spawn("sapling_moon")` 在玩家当前位置生成树苗，分别使用原版 `anim/sapling.zip` 与 `anim/sapling_moon.zip` 中与 prefab 同名的 bank 和 build，按 `sapling.lua` 从随机帧开始循环播放 80 帧 `sway`。树苗与草丛共用 `packages/prefab/src/pickablePlant.ts` 的组件实现，只在 prefab 定义上不同：左键通用 `PICK` 获得 1 个 `twigs` 并播放 `picked`（玩家采摘不播放 `picksound`，该字段只由 WX-78 状态图读取）；再生为 `TUNING.SAPLING_REGROW_TIME` 1920 游戏秒，春季登记任务时乘 0.75，冬季暂停，到期播放 `grow → sway`。装备 `shovel` / `goldenshovel` 右键 `DIG`：成熟树苗掉落 `twigs` 和 `dug_sapling`（月亮树苗为 `dug_sapling_moon`），已采摘的只掉落挖起的树苗。装备 `torch` 右键“点燃”，燃烧 20 游戏秒后生成 1 个 `ash` 并移除，燃烧期间不可采摘也不写入存档。`c_save()` 保存树苗 ID、脚点、采摘／暂停状态和剩余再生时间，读档按 `Pickable:OnLoad` 直接显示 `empty`；旧存档的空组件树苗恢复为成熟状态。`c_give("dug_sapling", 2)` / `c_give("dug_sapling_moon")` 给予挖起的树苗，每叠最多 10 个，`c_spawn("dug_sapling")` / `c_spawn("dug_sapling_moon")` 生成地面物品（`dropped` 姿态，库存图标分别来自 `inventoryimages.xml` / `inventoryimages2.xml`），也可点燃。已采摘的树苗带 `silviculture` 标签，可被《应用造林学》催生。重新栽种、枯萎和万圣节月亮转换尚未接入。

`c_spawn("bookstation")` 在玩家前方生成书架（`bookstation.lua`，bank/build `bookstation`，容器面板为 `ui_bookstation_4x5` 的 4×5 共 20 格，槽位按原版 `containers.lua` 的 `(-114 + 75*x, 37 - 79*y)` 相对动画原点排列，背景与槽位随窗口缩放对齐，槽位保持物品栏大小；可用 `reskin_tool` 换为 `bookstation_house` 皮肤）。左键走近打开，只接受带 `bookcabinet_item` 标签的物品：本项目中为 `book_silviculture`、`book_rain` 和 `papyrus`（`cookbook` 尚未接入）。开关容器播放 `hit` 后回到待机，并播放 `dontstarve/wilson/chest_open` / `chest_close`；玩家靠近时循环 `proximity_loop`，离开回到 `idle`；放置时播放 `place` 与 `wickerbottom_rework/bookstation/place`。书的数量决定 `empty` / `mid` / `full` 三层书堆：任一书（`book` 标签）入架即登记 30 游戏秒的周期任务，每期为架上每本未满的书恢复 1% 最大耐久（5 次耐久即 0.05 次），12 单位（36 场景单位）内有带 `bookbuilder` 标签的玩家时翻倍；书全部取出后任务取消，任务不写入存档，读档按架上内容重新登记。锤子需 4 次命中，锤毁时掉出所有物品并按配方 50% 掉落 `livinglog`、`papyrus`、`featherpencil`（后两者现可用 `c_give("papyrus", 4)` / `c_give("featherpencil")` 获取，`c_spawn` 同样可用；`featherpencil` 每叠 20）。书架可燃（燃烧 30 秒，火焰等级 4，大型传播器），烧毁后容器内物品掉出。`c_spawn("bookstation"); c_give("book_rain"); c_give("papyrus", 3)` 后把物品放入书架，再 `c_save()` 可验证书的剩余耐久（含 0.01 步长的小数值）、容器内容、位置和皮肤保存恢复。恢复耐久使用 `finiteuses` 的 `setPercent`，因此背包里的书耐久也可能带 0.01 步长的小数（所有书统一按 0.01 校验）。配方中 `bookbuilder` 限制、`BOOKCRAFT` 科技树和原型机（`prototyper`）的制作加成、`craft` 动画与 `wickerbottom_rework/bookstation/craft` 声音尚未接入，因为项目里还没有科技制作系统；`MiniMapEntity` 图标也未接入。

`c_spawn("pond")` 在玩家当前位置生成池塘，使用原版 `anim/marsh_tile.zip` 的 bank/build `marsh_tile` 和循环 `idle` 动画，贴图平铺在地面上并绘制在角色下方。当前仅实现池塘外观，不包含交互、碰撞、鱼蛙生成、岸边植物或季节变化；位置随 `c_save()` 保存并在加载时恢复。
