# 优化：配方按钮预创建，分类切换只做显示/隐藏

## 问题
每次切换分类都销毁并重建所有配方按钮。CHARACTER 分类有 ~253 个配方，CRAFTING_STATION 有 ~387 个。每个按钮创建涉及 DOM 元素、2-3 个 canvas、2 个同步 effect，导致明显卡顿。

## 方案

### 1. `initializeControls` 中预创建所有按钮

```ts
// 创建所有配方按钮（只执行一次）
const allRecipeButtons = new Map<string, HTMLButtonElement>();
for (const category of categories) {
  for (const recipe of category.recipes) {
    if (!allRecipeButtons.has(recipe.id)) {
      allRecipeButtons.set(recipe.id, mapRecipeToButton(recipe, allRecipeButtons.size));
    }
  }
}

// 快捷栏按分类缓存
const quickbarCache = new Map<string, HTMLButtonElement[]>();
```

### 2. 修改 `mapRecipeToButton` 的 click handler

当前 click handler 捕获了 `index`（分类内索引）。预创建后按钮不属于任何分类，需要改为按 recipe ID 查找当前分类内的索引：

```ts
button.addEventListener('click', () => {
  const idx = activeRecipes.findIndex(r => r.id === recipe.id);
  if (idx >= 0) updateSelection(idx);
});
```

这意味着 `selectRecipe` 的签名从 `(index: number) => void` 改为不需要了，因为 handler 直接在 mapper 里闭包捕获 `activeRecipes`。或者把 `selectRecipe` 改为接收 `recipeId`。

**最简改法**：mapper 不再接收 `selectRecipe` 回调，改为接收一个 `onSelect: (recipeId: string) => void`，在 `initializeControls` 里定义：

```ts
const onRecipeSelect = (recipeId: string) => {
  const idx = activeRecipes.findIndex(r => r.id === recipeId);
  if (idx >= 0) updateSelection(idx);
};
```

### 3. 修改 `renderCategoryRecipes`

不再销毁重建，只做 DOM 操作：

```ts
const renderCategoryRecipes = (category: CategoryConfig) => {
  activeCategoryIdState.set(category.id);
  activeRecipes = category.recipes;
  const preservedIndex = activeRecipes.findIndex(({ id }) => id === this.selectedRecipeId);
  selectedIndex = preservedIndex < 0 ? 0 : preservedIndex;

  // 移除旧按钮（不销毁，只从 DOM 摘除）
  recipeGrid.replaceChildren();
  quickbar.replaceChildren();

  // 添加当前分类的按钮
  const fragment = document.createDocumentFragment();
  for (const recipe of activeRecipes) {
    const btn = allRecipeButtons.get(recipe.id);
    if (btn) fragment.append(btn);
  }
  recipeGrid.append(fragment);

  // 快捷栏
  let quickButtons = quickbarCache.get(category.id);
  if (!quickButtons) {
    quickButtons = activeRecipes.slice(0, 10).map((recipe, index) => {
      const button = document.createElement('button');
      button.type = 'button';
      button.className = 'craft-quick-item';
      button.setAttribute('aria-label', recipe.name);
      button.dataset.label = recipe.name;
      button.append(recipeIcon(recipe));
      button.addEventListener('click', () => updateSelection(index));
      return button;
    });
    quickbarCache.set(category.id, quickButtons);
  }
  quickbar.append(...quickButtons);

  updateSelection(selectedIndex);
};
```

### 4. 不再需要 `recipeButtonEffects` 数组和 dispose 逻辑

按钮只创建一次，effects 生命周期跟按钮一致。`renderCategoryRecipes` 里的 `this.recipeButtonEffects.splice(0).forEach(dispose)` 删除。

`mapRecipeToButton` 不再需要 `effects` 参数。effects 直接跟着按钮走，按钮被 GC 时 effects 自然清理。

### 5. 清理 `disposeEffects`

`recipeButtonEffects` 相关逻辑全部移除。`controlEffects` 保留（用于 `refreshBuildButton` effect）。

## 修改文件

### `packages/ui/src/craft-recipe-button.ts`
- 移除 `effects` 参数和相关逻辑
- `selectRecipe: (index: number) => void` 改为 `onSelect: (recipeId: string) => void`
- click handler 改为 `onSelect(recipe.id)`
- 2 个 `createEffect` 保留（lock 图标和 buffered 背景），直接注册在按钮上，不需要外部 effects 数组

### `packages/ui/src/crafting-ui.ts`
- `initializeControls` 中预创建所有配方按钮（Map<recipeId, HTMLButtonElement>）
- 快捷栏按分类缓存（Map<categoryId, HTMLButtonElement[]>）
- `renderCategoryRecipes` 改为只做 DOM append，不再创建/销毁按钮
- 移除 `recipeButtonEffects` 字段和 `disposeEffects` 中的清理逻辑
- `mapRecipeToButton` 调用去掉 `effects` 参数，`selectRecipe` 改为 `onSelect`

## 验证

- 切换分类不再有卡顿
- lock 图标和 buffered 背景仍然正确响应 `setMaterialSummary` / `setBufferedRecipes`
- 快捷栏正确显示每个分类的前10个配方
- 选中配方、detail 面板、skin 切换功能不变
